    00

    开始之前：搞清楚沙箱是什么

    个人开发者无需营业执照，也能跑通全链路

    沙箱是支付宝官方给开发者的、与生产环境完全隔离的联调测试环境。官方对它的三个特性和盘托出：使用账号不需要任何资质、账号不需要开通任何权限、调用不影响生产数据。所以本教程全程可以用一个普通个人支付宝账号完成。

    阶段需要什么需要营业执照吗
    登录开放平台 / 进入沙箱个人支付宝账号 + 实名认证不需要
    沙箱联调（下单 / 支付 / 回调 / 退款）沙箱 APPID + 一对 RSA2 密钥不需要
    生产环境正式收款签约具体支付产品通常需要，视主体类型而定

    说明

    沙箱不是生产环境

    沙箱并非 100% 与生产一致。沙箱返回的数据（如用户 ID）在生产环境并不存在；沙箱里跑通后，上线前仍需在生产环境验收。本教程只覆盖沙箱练习。

    动手前请先确认
    01

    进入沙箱并创建应用

    在沙箱控制台拿到 APPID、网关和买家账号

    1. 打开官方沙箱应用页并登录（手机支付宝扫码最快）。
    2. 若页面右上角出现「升级沙箱环境」入口，先升级——老沙箱正在逐步暂停维护，新接入直接用新沙箱。
    3. 进入 开发信息，确认接口加签方式为 RSA2，并选择「自定义密钥」。
    4. 在 沙箱账号 页找到买家账号与登录密码，付款时会用到。
    要记下的值从哪里拿后面用在哪
    沙箱 APPID沙箱应用 · 开发信息SDK 初始化 appid
    支付宝网关沙箱应用页拼接支付跳转地址
    沙箱买家账号 / 密码沙箱账号页付款时登录沙箱

    坑点

    不要复用生产应用的 APPID

    沙箱有独立的 APPID 与网关，和生产环境完全不通用。混用会出现 isv.invalid-app-id 之类的报错。

    02

    生成并配置 RSA2 密钥

    先分清「应用公钥」和「支付宝公钥」

    支付宝要求用 RSA2 加签。可以用官方「支付宝开放平台开发助手」生成，也可以直接用命令行生成一对：

    1. 把生成的 app_public_key.pem（应用公钥）内容粘贴到沙箱应用的自定义密钥里并保存。
    2. 保存后，页面会给出一个支付宝公钥，把它存成 alipay_public_key.pem。
    3. app_private_key.pem（应用私钥）留在你的项目里，用来给请求签名，绝不外传。

    坑点

    验签失败的头号原因：两把公钥搞反了

    app_private_key.pem 是你自己的私钥；alipay_public_key.pem 是平台发给你的支付宝公钥。回调验签用的是支付宝公钥，不是你自己生成的那把。另外 .pem 文件头尾的 -----BEGIN/END----- 一行都不能少。

    技巧

    别把密钥提交进版本库

    在 .gitignore 中加入 keys/，或把密钥放进环境变量 / 密钥管理服务。私钥泄露等于别人可以冒充你的应用。

    03

    安装 SDK 并配置 Django

    一处配置沙箱网关，全局复用

    坑点

    网关地址必须和沙箱一致

    python-alipay-sdk 在 debug=False 时默认指向生产网关 openapi.alipay.com，在 debug=True 时指向旧沙箱网关。两种都不会自动变成新沙箱，所以要用 alipay._gateway 显式覆盖成 ALIPAY_GATEWAY。

    04

    下单视图：生成支付跳转

    先在本地落一笔订单，再跳去支付宝

    支付的第一步是先在自己的库里创建订单，拿到唯一订单号 out_trade_no，然后用它向支付宝换取支付链接。

    坑点

    total_amount 传 float 会挂

    金额单位是元，并必须以字符串传入。用 Decimal 存字段，传参时 str(order.amount)；不要传 float，也别带货币符号。

    05

    异步回调：验签、核账、幂等

    notify_url 才是订单状态变化的唯一可信来源

    支付回调有两个地址，职责完全不同：return_url（同步）只是付款后浏览器跳回的页面，可以被绕过、用户也可能直接关掉，不能用来改订单状态；notify_url（异步）是支付宝服务器直接 POST 到你的后端，这才是唯一可信源。

    • 验签：用支付宝公钥校验签名，签名不过直接拒绝。
    • 校 app_id：确认通知来自自己的应用。
    • 校金额：total_amount 是否与订单一致。
    • 幂等：先判断是否已支付，重复通知不重复发货。
    • 返回 success：处理成功必须回纯文本 success。

    坑点

    视图必须 @csrf_exempt

    支付宝的 POST 没有 CSRF token，不豁免会被 Django 直接 403，表现为「回调一直没收到」或「验签前就失败」。

    坑点

    返回内容不能是 HTML 或 JSON

    支付宝只认纯文本 success。返回 {"ok": true} 或带 BOM/空白的字符串，都会被判定为失败并触发重推。

    06

    内网穿透：让支付宝能回调到本地

    127.0.0.1 无法被支付宝服务器访问

    本地开发的 localhost:8000 对支付宝服务器不可见，所以必须用内网穿透把本地端口暴露成公网地址，并把这个地址写进 ALIPAY_NOTIFY_URL。

    • 把 ngrok 给出的公网地址填写到 settings.ALIPAY_NOTIFY_URL，路径与路由一致（如 /api/alipay/notify/）。
    • 免费隧道地址每次重启都会变，改完记得同步更新配置并重启 Django。
    • 确认该地址公网可直接访问，且返回的不是 Django 的 403 / 404。

    技巧

    先自测一次可达性

    用 curl -X POST https://你的隧道地址/api/alipay/notify/ 打一次，若返回 failure（而不是超时或 403），说明链路已经通了。

    07

    联调实测：完整走一遍支付

    用沙箱买家账号真实付款并观察回调

    1. 浏览器访问 /pay/create/，会被重定向到支付宝沙箱收银台。
    2. 用沙箱买家账号登录并付款（不是你的正式支付宝账号）。
    3. 付款成功后观察 Django 控制台：notify 视图是否被 POST 调用、日志里有没有「验签失败」。
    4. 回数据库看订单 status 是否变为 paid、trade_no / paid_at 是否写入。
    5. 在沙箱控制台对同一订单发起一次退款，验证退款链路（注意沙箱限制）。
    观察点预期结果
    支付页是否正常打开显示沙箱收银台，金额与订单一致
    notify 是否被调用控制台出现 POST 请求日志
    验签无「验签失败」告警
    订单状态由 pending 变为 paid，写入 trade_no / paid_at
    重复通知再次收到同订单通知时不会重复处理

    说明

    沙箱的退款限制

    沙箱环境里，退款金额必须与支付金额完全一致，且每笔订单只支持调用一次退款接口。练习时别按「部分退款 / 多次退款」去设计用例。

    08

    常见坑速查

    报错对照表，先查这里

    现象可能原因怎么处理
    验签失败 / invalid-signature「应用公钥」被当成了「支付宝公钥」私钥用你生成的，支付宝公钥用平台给的那把
    isv.invalid-app-id用了生产或旧沙箱的 APPID / 网关确认 APPID 与网关都来自沙箱应用页
    回调一直没触发notify_url 非公网可达，或被 CSRF 拦截检查内网穿透地址，给视图加 @csrf_exempt
    同一通知被反复重推处理完没返回纯文本 success成功时返回 HttpResponse("success", content_type="text/plain")
    订单被重复置为已支付没有做幂等判断先查订单状态，已支付就直接返回 success
    金额相关报错total_amount 传了 float 或带货币符号用 Decimal 存，传 str(order.amount)，单位元
    沙箱退款失败退款金额与支付不一致，或已退过沙箱要求金额相等，且每单只能退一次

    说明

    沙箱跑通 ≠ 生产可用

    本教程只覆盖沙箱练习。生产环境需要签约具体支付产品、使用正式 APPID 与网关，并按官方要求重新验收。切换时把 ALIPAY_APPID、ALIPAY_GATEWAY、密钥和回调域名整体替换即可。

    本手册仅覆盖支付宝沙箱环境的练习流程，示例代码为最小可运行实现。接入生产环境前，请以 支付宝官方文档 为准重新验收。
