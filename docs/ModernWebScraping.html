合规与职业红线

入行第一课：知道什么不能爬，比知道怎么爬更重要

现代爬虫岗位面试，合规意识几乎是必问题。企业不想招一个会把公司送上法庭的人。这一章看似"软"，实则是求职硬通货。

1. 必须了解的法律与规范

法规 / 规范与爬虫的关系
《网络安全法》禁止非法侵入网络、干扰网络正常功能；不得窃取个人信息。
《数据安全法》数据分级分类，重要数据不得擅自采集、交易。
《个人信息保护法》(PIPL)采集姓名/手机/身份证/人脸等个人信息需授权，敏感信息需单独同意。
《刑法》285/286 条非法获取计算机信息系统数据罪、破坏计算机信息系统罪——绕过技术保护措施可能触犯。
robots.txt行业惯例，声明抓取意愿；虽然不具强制法律效力，但违反是重要负面信号。
网站用户协议 / ToS合同中常明确禁止自动化访问，违约可构成不正当竞争。
⚠️ 绝对不要碰的红线 ① 绕过登录/权限抓取用户隐私数据；② 破解验证码批量注册/撞库；③ 抓取后贩卖、泄露个人信息；④ 高频请求导致对方服务瘫痪（可能构成破坏计算机信息系统罪）；⑤ 金融、医疗、未成年人敏感数据。这些不是"技术挑战"，是刑事风险。

2. 合规爬取的自检清单

  • 先看后爬：检查 robots.txt、网站 ToS、是否有开放 API（优先用 API）。
  • 最小必要：只采集业务必需的字段，不采个人敏感信息。
  • 控制频率：设置合理延时与并发上限，遵守对方承载能力，避开高峰。
  • 表明身份：UA 中如实标注爬虫与联系方式（便于对方联系）。
  • 数据用途合法：采集数据仅用于约定用途，妥善存储、脱敏、定期删除。
🎯 面试高频问："你如何保证爬虫合规？" 参考答法：先讲 robots.txt 与 ToS 检查 → 优先官方 API → 最小必要字段与脱敏 → 频率控制与限速 → 数据合规存储与用途限定 → 遇到明确禁止则停止。再补一句"我会评估商业与法律风险，必要时让法务介入"。这套回答在绝大多数公司都能拿分。

🍪

Cookie / Session

维持登录态的关键；理解 Session 复用、Cookie Jar 自动管理、Token 刷新机制。

🔐

HTTPS / TLS

证书校验、TLS 指纹（JA3/JA4）已成为高级反爬手段，后面章节会讲应对。

请求响应模型（爬虫视角）

# 一次请求 = 方法 + URL + Headers + Body + Cookie
# 一次响应 = 状态码 + Headers + Cookie + Body(HTML/JSON/二进制)

import httpx

resp = httpx.get(
    "https://example.com/api/list",
    headers={"User-Agent": "Mozilla/5.0 ...", "Referer": "https://example.com/"},
    params={"page": 1, "size": 20},
    timeout=10,
)
print(resp.status_code, resp.url, resp.headers.get("content-type"))
print(resp.text)        # 文本（HTML/JSON 字符串）
print(resp.json())      # 自动解析 JSON
print(resp.content)     # 二进制（图片/文件）

理解 resp 的各属性，是后续一切解析与存储的前提。

抓取库与异步并发

从 requests 到 httpx / aiohttp，构建高并发抓取能力

技术选型：2026 年该用哪个？

库特点适用场景建议
requests同步、生态成熟、简单稳定小规模、低频、Demo、调试必会，但新项目不首选
httpx 现代首选同步/异步双支持、HTTP/2、类型提示完善新项目、需要处理 HTTP/2重点掌握
aiohttp纯异步、性能高、生态久高并发异步爬虫了解 + 会用
curl_cffi 反爬利器模拟真实浏览器 TLS/JA3 指纹对抗 TLS 指纹检测的站点进阶必知

从 requests 到 httpx 的平滑迁移

import httpx

# 同步 client（复用连接池，比逐个 get 高效）
with httpx.Client(
    headers={"User-Agent": "Mozilla/5.0 ..."},
    timeout=httpx.Timeout(10.0),
    follow_redirects=True,
) as client:
    r = client.get("https://example.com", params={"q": "python"})
    print(r.status_code, r.text[:200])

异步并发：爬虫性能的分水岭

爬虫是典型的 I/O 密集型任务——大部分时间花在等网络响应。用异步/concurrent 可以把等待时间重叠起来，吞吐提升一个数量级。

import asyncio, httpx

urls = [f"https://example.com/page/{i}" for i in range(100)]

async def fetch(client, url):
    try:
        r = await client.get(url)
        return url, r.status_code, r.text[:100]
    except httpx.RequestError as e:
        return url, "ERR", str(e)

async def main():
    limits = httpx.Limits(max_connections=20)  # 控制并发，别把对方打挂
    async with httpx.AsyncClient(limits=limits, timeout=10) as client:
        tasks = [fetch(client, u) for u in urls]
        results = await asyncio.gather(*tasks)
    for u, s, t in results:
        print(s, u)

asyncio.run(main())

要点：用 Semaphore 或 Limits 控制并发数；配合重试与限速；异常不要让它中断整个任务。

生产级请求必备三件套

  • 重试：httpx 配合 tenacity，对 5xx/超时做指数退避重试。
  • 超时：一定设置 connect/read/write/pool 分段超时，防止任务永久挂起。
  • 限速：用 asyncio.Sleep 或令牌桶，控制 QPS，既是礼貌也是防封。

CSS 与 XPath 对照（重点掌握）

from parsel import Selector

html = """


  Python 爬虫实战
  ￥99


"""
sel = Selector(html)

# CSS 选择器
sel.css("a.title::text").get()          # 'Python 爬虫实战'
sel.css("a.title::attr(href)").get()     # '/detail/1'
sel.css("div.item").getall()             # 所有 div.item 节点

# XPath（更灵活，可向上/兄弟轴）
sel.xpath("//div[@class='item']/a/text()").get()
sel.xpath("//a[@class='title']/@href").get()
sel.xpath("//span[contains(@class,'price')]/text()").get()

# 提取列表并结构化
for item in sel.css("div.item"):
    print({
        "title": item.css("a.title::text").get(),
        "url":   item.css("a.title::attr(href)").get(),
        "price": item.css("span.price::text").get(),
    })

::text 取文本，::attr() 取属性；XPath 用 /text() 与 /@attr。两套都要会。

动态页面与浏览器自动化

当数据由 JavaScript 渲染时，如何优雅地拿到它

什么时候才需要浏览器？

很多爬虫性能问题，根源是滥用无头浏览器。正确顺序是：

  1. 先看 Network 有没有直接的 JSON 接口 → 有就直接请求（最快最稳）；
  2. 看 HTML 源码里是否已内嵌数据（如 window.__INITIAL_STATE__）→ 解析它；
  3. 以上都不行，再上 Playwright 渲染。
⚠️ 性能提醒 无头浏览器内存/CPU 开销是 requests 的几十倍，速度慢一个数量级。生产环境把它当"最后手段"，并做好浏览器实例复用、页面池化、并发控制。

Playwright（现代首选） vs Selenium

维度PlaywrightSelenium
架构新一代，CDP 原生，跨浏览器（Chromium/Firefox/WebKit）老牌，WebDriver 协议
速度 & 稳定性快、自动等待机制好相对慢，需手动等待
异步支持原生 async API有限
反检测生态好（ stealth 插件、CDP 隐藏指纹）一般
建议新项目首选老项目维护、兼容性场景

Playwright 实战模板

from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)
    ctx = browser.new_context(
        user_agent="Mozilla/5.0 (Windows NT 10.0; Win64; x64) ...",
        viewport={"width": 1280, "height": 800},
        locale="zh-CN",
    )
    page = ctx.new_page()
    page.goto("https://example.com", wait_until="networkidle")

    # 等待关键元素出现
    page.wait_for_selector(".item")
    titles = page.locator(".item .title").all_text_contents()

    # 拦截接口响应，直接拿 JSON（高级技巧）
    with page.expect_response("**/api/list**") as resp_info:
        page.click("button.load-more")
    data = resp_info.value.json()

    ctx.close(); browser.close()

技巧：用 expect_response / page.on("response") 直接捕获接口数据，跳过 DOM 解析。

反检测基础（浏览器指纹对抗）

  • 隐藏 navigator.webdriver 等自动化特征（stealth 脚本 / CDP 注入）。
  • 伪造 UA、屏幕分辨率、时区、语言、WebGL / Canvas 指纹。
  • 模拟真人行为：随机滚动、鼠标移动、点击间隔（对抗行为分析）。
  • 复用 Cookie / 登录态，避免每次都是"新访客"。

Scrapy 框架与分布式

企业级爬虫的标配框架，中高级岗位的分水岭
✅ 为什么说 Scrapy 是求职必会 招聘 JD 里出现频率最高的框架，没有之一。它把调度、去重、重试、并发、管道化存储、中间件扩展全部工程化。会用 requests 是"会写脚本"，会用 Scrapy 才叫"会做爬虫工程"。

Scrapy 架构（务必理解数据流）

组件职责面试要点
Engine核心引擎，驱动各组件间的数据流协调整体
Scheduler请求队列 + 去重指纹去重原理（request fingerprint）
Downloader发起请求，返回 Response异步基于 Twisted

spider —— 解析并产出：

import scrapy
from myproj.items import ProductItem

class ProductSpider(scrapy.Spider):
    name = "product"
    start_urls = ["https://example.com/list"]

    custom_settings = {"DOWNLOAD_DELAY": 1, "CONCURRENT_REQUESTS": 8}

    def parse(self, response):
        for box in response.css("div.item"):
            yield ProductItem(
                title=box.css("a.title::text").get(),
                price=box.css("span.price::text").get(),
                url=response.urljoin(box.css("a::attr(href)").get()),
                source="example",
            )
        # 翻页：构造下一页请求，回调自身
        nxt = response.css("a.next::attr(href)").get()
        if nxt:
            yield response.follow(nxt, callback=self.parse)

中间件：UA 与代理的经典写法

import random
class RotateMiddleware:
    def __init__(self, uas):
        self.uas = uas
    @classmethod
    def from_crawler(cls, crawler):
        return cls(crawler.settings.getlist("USER_AGENTS"))
    def process_request(self, request, spider):
        request.headers["User-Agent"] = random.choice(self.uas)
        # 代理：request.meta["proxy"] = "http://ip:port"

分布式爬虫：scrapy-redis

当单机不够用时，用 Redis 作为共享的请求队列与去重集合，多台机器协同抓取：

  • Scheduler 换成 Redis 队列 → 多机共享待抓任务；
  • DUPEFILTER_CLASS 换成 Redis 去重 → 多机共享已抓指纹，避免重复；
  • 主节点负责产出初始请求（seed），从节点消费队列。

代理 IP 池设计（工程重点）

  • 来源：机房代理（便宜、易被识别）、住宅代理（贵、更真实）、隧道代理（自动轮换）。
  • 调度：按权重/响应速度分配，失败自动剔除，定期健康检测。
  • 成本控制：按量付费场景要精确计算所需 IP 数与请求成功率。

JS 逆向入门（进阶/高薪方向）

当关键参数由 JS 生成时，需要逆向。基本套路：

定位加密位置

全局搜索参数名 / 断点调试（Sources / 抓包对比），找到生成签名的函数。

分析算法逻辑

看是标准加密（MD5/AES/RSA）还是自定义；关注关键变量来源。

复现或执行

用 Python 重写算法，或用 execjs / Node.js 直接执行原 JS，或"补环境"让 JS 在 Node 中跑起来。

hook 与自动化

用 Fiddler/mitmproxy 拦截替换 JS，或用 js hook 固定关键函数输出，降低调试难度。
import execjs

with open("sign.js", encoding="utf-8") as f:
    ctx = execjs.compile(f.read())

sign = ctx.call("getSign", "page=1&size=20")  # 调用 JS 函数生成签名
# 再把 sign 拼进请求参数
⚠️ 合法边界 JS 逆向技术本身是中性的，但仅可用于你有授权的数据采集。绕过技术保护措施去抓取受保护数据，可能触犯《刑法》285 条。面试中谈逆向时要强调"在授权范围内"。

TLS / JA3 指纹（现代高级反爬）

即使你伪造了 UA，服务器仍能通过 TLS 握手特征（JA3/JA4 指纹）识别出你是 Python 客户端。应对方案：curl_cffi 模拟真实浏览器的 TLS 指纹，这是 2026 年进阶爬虫的必备技能。

from curl_cffi import requests as cffi_requests

resp = cffi_requests.get(
    "https://example.com",
    impersonate="chrome120",  # 模拟 Chrome 的 TLS 指纹
)
print(resp.status_code, resp.text[:100])

存储与工程化部署

从"能跑的脚本"到"可维护、可监控的生产系统"

存储选型

存储适用数据爬虫场景
MySQL / PostgreSQL结构化、需事务业务数据落库、任务状态管理
MongoDB半结构化、字段多变网页原始 JSON、字段不固定的采集
Redis高速缓存、队列、去重请求队列、去重集合、代理池、限流计数
Elasticsearch全文检索、海量文档内容搜索、日志分析、去重相似度
对象存储（S3/OSS）图片/文件原始页面快照、媒体资源归档
💡 典型分层架构 Redis 做调度队列与去重 → Spider 抓取 → 结构化数据入 MySQL，原始/非结构化入 MongoDB → 需检索的同步进 ES。消息队列（Kafka/RabbitMQ）用于爬虫与下游业务解耦。

去重策略（面试常考）

  • URL 去重：Scrapy 请求指纹 / Redis set，最简单常用。
  • 内容去重：对正文做 SimHash / MinHash，识别"改标题的转载文"。
  • 布隆过滤器：海量 URL 去重，省内存（有误判率，可用 RedisBloom）。

调度与常驻运行

  • crontab / APScheduler：定时触发抓取任务（轻量）。
  • Celery + Beat：分布式任务队列，适合复杂调度与异步处理。
  • scrapyd：Scrapy 项目的部署与定时调度 daemon。

Docker 部署要点

  • 用 docker-compose 编排 Redis / MySQL / 爬虫服务；

可观测性：日志、监控、告警

  • 关键指标：请求成功率、响应码分布、每秒抓取量、被封 IP 数、入库量。
  • 告警：成功率骤降 / 长时间无数据时自动通知（邮件 / 钉钉 / 企业微信）。
  • 重试与幂等：失败请求持久化重试，入库做唯一键避免重复。

3 个可直接写进简历的项目，含技术栈、亮点与量化话术
💡 选项目的原则 不要写"爬了某某网站"这种流水账。要体现工程复杂度：分布式、反爬对抗、数据质量、调度监控、性能数字。用 STAR + 量化指标 包装（QPS、数据量、成功率、提速倍数）。

项目一：电商商品价格监控系统 中高级

技术栈

Scrapy + scrapy-redis + MySQL + Redis + APScheduler + Docker + 简单可视化（FastAPI/ECharts）

  • 需求：监控 N 个电商平台的商品价格/库存变化，价格低于阈值自动告警。
  • 难点与亮点：多站点适配器模式；代理 IP 池 + UA 轮换应对反爬；SKU 去重与价格历史时序存储；分布式抓取（3 节点）；定时增量更新。
  • 量化话术："实现分布式采集，日均抓取 X 万条，成功率 98%，相比单机提速 3 倍；通过代理池与限速将 IP 封禁率降到 1% 以下。"

项目二：招聘/新闻信息聚合平台 中高级

技术栈

httpx/aiohttp + asyncio + MongoDB + Elasticsearch + Kafka + Celery

  • 需求：聚合多来源岗位/资讯，去重、分类、全文检索，对外提供 API。
  • 难点与亮点：异步高并发抓取；SimHash 内容去重（识别跨站转载）；Kafka 解耦采集与清洗；ES 全文检索与聚合分析。
  • 量化话术："异步架构下单机 QPS 达到 X，去重准确率 95%+，支撑 X 万条数据的秒级检索。"

项目三：动态渲染站点采集 & 反爬系统 进阶/高薪

技术栈

Playwright + curl_cffi + execjs/Node + mitmproxy + Redis + MySQL

  • 需求：采集强反爬、数据由 JS 渲染的站点（在授权范围内）。
  • 难点与亮点：抓包定位真实接口；JS 签名参数逆向并复现；Playwright 浏览器池复用 + stealth 反检测；TLS 指纹模拟；验证码与登录态管理。
  • 量化话术："通过接口直取替代页面渲染，性能提升 10 倍；逆向签名算法实现稳定自动采集，维护成本降低 70%。"

高频面试题库

按主题分类，每题给出回答要点，用于自检与查漏

A. 基础与网络

  1. 一次 HTTP 请求包含哪些部分？常见状态码有哪些？
    请求行/头/体；2xx/3xx/4xx/5xx，重点说 301/302、403、429、500 的含义与爬虫处理。
  2. GET 与 POST 的区别？
    参数位置、语义、长度限制、安全性（都不是真正安全）、缓存行为。
  3. Cookie 与 Session 的区别和联系？
    Session 存服务端，Cookie 存客户端并携带 sessionid；爬虫如何维持登录态。
  4. HTTPS 原理简述？证书校验在爬虫中如何配置？
    非对称+对称加密混合；verify 参数、忽略证书的风险。
  5. 什么是 HTTP/2？对爬虫有什么影响？
    多路复用、头部压缩、二进制帧；httpx 支持，指纹特征不同。
  6. requests 中 Session 的作用？
    连接复用（性能）、自动管理 Cookie。
  7. 遇到 403/429 如何排查？
    UA/Referer/Cookie/频率/IP/指纹，逐层排查。

B. 解析与框架

  1. CSS 选择器与 XPath 的区别？各举一例。
    语法与能力差异，XPath 可轴选择，CSS 更简洁。
  2. BeautifulSoup 与 lxml 的区别？
    纯 Python vs C 实现，容错性 vs 速度，解析器选择。
  3. Scrapy 的架构和数据流？
    Engine/Scheduler/Downloader/Spider/Pipeline 及数据流转顺序。
  4. Scrapy 如何实现去重？
    请求指纹 + 集合；分布式用 Redis 共享集合。
  5. 下载中间件与蜘蛛中间件的区别？
    生效阶段不同：请求/响应处理 vs spider 输入输出处理。
  6. Scrapy 中如何设置代理和 UA？
    在 Downloader Middleware 的 process_request 中修改 request.meta / headers。
  7. pipelines.py 中 process_item 为什么要 return item？
    链式传递，否则后续 Pipeline 收不到数据。

C. 异步与性能

  1. 同步与异步爬虫的区别？为什么爬虫适合异步？
    I/O 密集型，等待时间可重叠，协程开销小。
  2. 协程、线程、进程的区别？GIL 的影响？
    调度单位、内存开销、并行性；I/O 释放 GIL，协程更适合高并发 I/O。
  3. asyncio 中 gather 与 create_task 的区别？
    gather 聚合多个协程结果，create_task 创建可独立管理的任务。
  4. 如何控制爬虫并发，避免打挂对方？
    Semaphore / 连接池上限 / DOWNLOAD_DELAY / 令牌桶限速 / AUTOTHROTTLE。
  5. 如何提升爬虫性能？
    找接口替代渲染、异步并发、连接复用、减少解析开销、增量抓取。

D. 反爬与工程

  1. 常见反爬手段及应对？
    按请求头/IP/验证码/JS/行为/指纹六类分层作答。
  2. 代理 IP 池如何设计？
    来源、调度、健康检查、失败剔除、成本控制。
  3. 遇到 JS 加密参数怎么办？
    抓包定位 → 调试分析 → Python 复现或 execjs 执行原 JS → 补环境。
  4. 什么是 JA3/TLS 指纹？如何应对？
    TLS 握手特征识别客户端库；curl_cffi 模拟浏览器指纹。
  5. 如何保证爬虫合规？
    robots/ToS、优先 API、最小必要、限速、脱敏、用途合法、停止机制。
  6. 分布式爬虫如何做？
    scrapy-redis：Redis 共享队列与去重集合；多节点消费。
  7. 爬虫挂了如何恢复？
    持久化请求队列与进度、断点续爬、幂等入库、失败重试。
  8. 如何监控爬虫？
    成功率、QPS、被封率、入库量、告警。

E. 开放/场景题（体现经验）

  1. 要抓一个从未见过的新网站，你的完整流程是什么？
    合规评估 → 抓包分析接口 → 判断静态/动态 → 选技术栈 → 小规模验证 → 反爬应对 → 工程化 → 监控。
  2. 数据量从 10 万涨到 1000 万，你的架构怎么演进？
    单机→异步→分布式→队列解耦→存储分片→增量与去重优化。
  3. 目标网站改版导致抓取失败，你怎么办？
    监控告警→定位变化→多重选择器兜底→优先接口→降低对 DOM 结构依赖。
  4. 如何设计一个通用的爬虫平台？
    配置化/插件化、任务调度、代理与指纹服务、数据管道、监控与权限。
